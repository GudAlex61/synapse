# Synapse — P2P-совместный просмотр видео

В этой версии локальный фильм **не загружается в Supabase, Vercel Blob, R2 или другой файловый сервис**. Владелец выбирает файл, браузер воспроизводит его локально, захватывает готовые аудио/видео дорожки и отправляет второму участнику напрямую через WebRTC.

## Как это работает

1. Первый участник выбирает локальный файл и становится владельцем трансляции.
2. В Supabase сохраняются только название файла, размер, идентификатор владельца и идентификатор P2P-сессии.
3. Второй участник сообщает через маленькое RPC-сообщение, что готов смотреть.
4. Браузеры обмениваются SDP offer/answer через Postgres и устанавливают прямой `RTCPeerConnection`.
5. Владелец управляет плеером. Его `play`, `pause`, перемотка и возврат к `0:00` отражаются в самом передаваемом медиапотоке; зритель получает read-only плеер.

Размер исходного файла не расходует облачное хранилище. Файл в 500 МБ, 5 ГБ или больше читается локально по мере воспроизведения. Реальный предел задают поддерживаемый браузером формат, производительность устройства и исходящая скорость владельца.

## Почему владелец является главным

Для локального P2P-файла не отправляются отдельные команды `play/pause/seek` зрителю. Это устраняет гонки, циклы событий и расхождение таймлайнов: единственным источником истины становится изображение и звук, которые реально выводит плеер владельца.

При перемотке в состоянии паузы Chrome может не опубликовать новый кадр в `captureStream()` сразу. Компонент делает скрытый импульс ровно до следующего видеокадра и снова ставит локальный плеер на паузу. Поэтому зритель получает новую позицию, но трансляция не продолжает играть.

Режим прямой URL сохранён. Для URL управление остаётся двусторонним и использует ревизии состояния из предыдущей версии.

## Требования и ограничения

- Рекомендуемые браузеры владельца: актуальные Chrome или Edge. Firefox также поддерживает медиазахват, но имеет собственные особенности реализации.
- `HTMLMediaElement.captureStream()` имеет неполную поддержку во всех браузерах. Добавлен запасной путь через `canvas.captureStream()` и Web Audio, но Safari следует считать best-effort режимом.
- Владелец должен держать страницу и файл открытыми. После закрытия или сна его вкладки поток прекращается.
- Исходящая скорость владельца должна быть достаточной для выбранного качества. Код просит браузер использовать до 12 Мбит/с, но WebRTC автоматически адаптируется к сети.
- WebRTC использует STUN для прямого соединения. Без TURN часть сочетаний CGNAT, симметричного NAT, VPN или корпоративных firewall не соединится. В такой ситуации приложение покажет понятную ошибку и автоматически повторит ICE-переговоры, но гарантировать связь на каждой сети без релея невозможно.
- P2P-соединение раскрывает участникам сетевые адреса друг друга через ICE. Для приватной комнаты из двух знакомых пользователей это ожидаемое свойство прямой связи.

## Настройка Supabase

### Уже применена `001_watch_rooms.sql`

Выполните только:

```text
supabase/migrations/003_p2p_streaming.sql
```

Миграция 003 самодостаточна после 001: она добавляет ревизии состояния, membership/heartbeat, таблицу маленьких WebRTC-сигналов, RPC-функции и очистку пустых комнат. Она также безопасно заменяет функции из старой миграции 002, если та уже была выполнена.

### Чистый проект

В SQL Editor последовательно выполните:

```text
supabase/migrations/001_watch_rooms.sql
supabase/migrations/003_p2p_streaming.sql
```

Миграция `002_reliable_sync_r2.sql` оставлена только как историческая для уже развёрнутых Git-проектов. Новому P2P-развёртыванию она не требуется при ручном применении SQL.

Если автоматическое создание Cron недоступно, включите **Integrations → Cron** и выполните:

```text
supabase/enable-cleanup-cron.sql
```

Очистка работает так:

- кнопка выхода удаляет участника сразу;
- если вышел последний участник, удаляются состояние, чат и WebRTC-сигналы комнаты;
- аварийно закрытая вкладка перестаёт считаться активной спустя 5 минут;
- Cron удаляет данные комнаты без активных heartbeat примерно через 10 минут.

## Переменные окружения

```env
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...

# Необязательно: значения по умолчанию уже встроены.
NEXT_PUBLIC_WEBRTC_ICE_SERVERS=stun:stun.cloudflare.com:3478,stun:stun.l.google.com:19302
```

Не помещайте постоянный пароль TURN в `NEXT_PUBLIC_*`: такая переменная видна браузеру. Если позднее понадобится TURN, используйте краткоживущие credentials, выдаваемые серверным endpoint.

## Ручной smoke-test двух пользователей

1. Откройте комнату в двух независимых окнах или браузерных профилях.
2. У владельца нажмите **«Выбрать и транслировать»** и выберите MP4/WebM.
3. Дождитесь статуса **«прямое соединение установлено»**.
4. Нажмите Play у владельца — зритель должен увидеть и услышать тот же момент.
5. Поставьте паузу — кадр зрителя должен замереть.
6. На паузе перемотайте ровно на 5 секунд — зритель должен увидеть новый кадр, оставаясь на паузе.
7. Перемотайте на 10 секунд и продолжите воспроизведение.
8. Верните таймлайн на `0:00` и нажмите Play — зритель должен увидеть начало.
9. Обновите страницу зрителя — он должен заново подключиться к активной трансляции.
10. Обновите страницу владельца. В Chrome/Edge приложение попытается восстановить сохранённый `FileSystemFileHandle`; если браузер запросит разрешение, нажмите **«Восстановить файл»**. При обычном `<input type=file>` браузер по правилам безопасности требует выбрать файл заново.

## Что хранится в Supabase

- состояние комнаты и метаданные источника;
- до 500 последних сообщений чата;
- heartbeat двух участников;
- временные SDP offer/answer и сигналы готовности, автоматически удаляемые через 10 минут.

Сами байты фильма, аудиодорожка и кадры в базе не сохраняются.

## Диагностика

В интерфейсе показываются:

- состояние P2P-соединения;
- оценка текущего битрейта;
- round-trip time;
- тип выбранных ICE-кандидатов;
- предупреждение при невозможности прямого соединения.

`socket closed: 1006` у Supabase Realtime больше не является причиной потери видео: WebRTC-сигналинг идёт через Postgres RPC polling, а Realtime используется только как ускорение чата и состояния URL-режима.
